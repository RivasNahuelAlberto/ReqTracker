[Troubleshooting](#troubleshooting)\n\n---\n\n## Introducción\n\n### ¿Por qué MCP en ReqTracker?\n\nReqTracker es una **plataforma full-stack compleja** deployada en Render.com con:\n\n- Frontend React + Vite\n- Backend Node.js + Express\n- Microservicio Python FastAPI (analytics)\n- MongoDB Atlas (persistencia)\n- Socket.io (comunicación real-time)\n- OAuth Google (autenticación)\n\n**Los desafíos:**\n- ❌ Errores en producción requieren lectura manual de logs en Render\n- ❌ Debugging remoto lento y tedioso\n- ❌ Correlacionar errores con código base es manual\n- ❌ No hay observabilidad en tiempo real desde VS Code\n\n**La solución:**\n- ✅ **MCP (Model Context Protocol)** - Protocolo estándar para agentes IA\n- ✅ **Continue** - Lee logs de Render, analiza infraestructura\n- ✅ **Cline** - Agente debugging autónomo en VS Code\n- ✅ **Observabilidad integrada** - Errores detectados automáticamente\n\n---\n\n## Qué es MCP\n\n### Definición\n\n**MCP (Model Context Protocol)** es un protocolo abierto que permite que **agentes IA e IDEs** se conecten con servicios externos (APIs, bases de datos, infraestructura) de forma segura y estructurada.\n\n### En ReqTracker, MCP permite:\n\n```\n┌─────────────┐\n│  VS Code    │\n│ Continue    │  ← IDE principal\n│ Cline       │\n└──────┬──────┘\n       │ MCP protocol\n       ↓\n┌─────────────────────────────────┐\n│  Render MCP Server              │\n│  ├─ Lectura de logs backend     │\n│  ├─ Estado de deploys           │\n│  ├─ Variables de entorno        │\n│  ├─ Métricas de servicios       │\n│  └─ Error tracking              │\n└─────────────────────────────────┘\n       │\n       ↓\n┌─────────────────────────────────┐\n│  Infraestructura Render.com     │\n│  ├─ Backend logs (Node.js)      │\n│  ├─ Deploy history              │\n│  ├─ Environment status          │\n│  └─ Runtime diagnostics         │\n└─────────────────────────────────┘\n```\n\n### Problemas que Resuelve\n\n| Problema | Solución MCP |\n|----------|-------------|\n| Logs enterrados en Render dashboard | MCP trae logs a VS Code en tiempo real |\n| No sé qué endpoint falló | MCP mapea error → endpoint → código |\n| Debugging toma 30+ min | Cline automatiza análisis en < 2 min |\n| No puedo ver estado en tiempo real | Continue + MCP = observabilidad live |\n| Errores producción no correlacionan | MCP correlaciona logs con stack traces |\n\n---\n\n## Setup en VS Code\n\n### Requisitos Previos\n\n✅ **Continue installed**\n```bash\n# En VS Code: Extensions → Search \"Continue\" → Install\n```\n\n✅ **Cline installed** (recomendado)\n```bash\n# En VS Code: Extensions → Search \"Cline\" → Install\n```\n\n✅ **Render API Key**\n```bash\n# Render.com → Account Settings → API Token\n# Guárdalo en variables de entorno (NO hardcodeado)\n```\n\n✅ **Node.js 18+**\n```bash\nnode --version  # v18.x o superior\n```\n\n### 1. Configurar Variables de Entorno\n\nCrea archivo `.env` en raíz del proyecto:\n\n```bash\n# .env (SOLO DESARROLLO - NUNCA COMMIT)\nRENDER_API_KEY=<tu-api-key-aqui>\nRENDER_SERVICE_ID=<service-id-backend>\nRENDER_REGION=oregon  # o region de tu servicio\n```\n\n✅ **Importante:** Agregar `.env` a `.gitignore`\n```bash\necho \".env\" >> .gitignore\n```\n\n### 2. Instalar Continue\n\n**Opción A: Marketplace (Recomendado)**\n```\n1. VS Code → Extensions\n2. Search: \"Continue\"\n3. Install (by Continue Dev)\n```\n\n**Opción B: CLI (Alternative)**\n```bash\nnpm install -g continue-cli\n```\n\n### 3. Configurar Continue para MCP\n\n**Archivo:** `.continue/config.json` (crear si no existe)\n\n```json\n{\n  \"models\": [\n    {\n      \"title\": \"Claude\",\n      \"provider\": \"anthropic\",\n      \"model\": \"claude-3-5-sonnet-20241022\",\n      \"apiKey\": \"${ANTHROPIC_API_KEY}\"\n    }\n  ],\n  \"mcp_servers\": {\n    \"render\": {\n      \"type\": \"render_mcp\",\n      \"config\": {\n        \"apiKey\": \"${RENDER_API_KEY}\",\n        \"serviceId\": \"${RENDER_SERVICE_ID}\",\n        \"region\": \"${RENDER_REGION}\"\n      }\n    }\n  },\n  \"context_providers\": [\n    {\n      \"name\": \"render\",\n      \"enabled\": true,\n      \"settings\": {\n        \"logLines\": 100,\n        \"includeMetrics\": true,\n        \"autoRefresh\": true,\n        \"refreshInterval\": 30000\n      }\n    }\n  ]\n}\n```\n\n### 4. Instalar Cline\n\n**En VS Code:**\n```\n1. Extensions → Search \"Cline\"\n2. Install (by Anthropic)\n3. Configure con misma API key de Claude\n```\n\n### 5. Verificar Configuración\n\n**Test en VS Code Continue:**\n\n```\n/shell echo \"Testing MCP connection...\"\n@render status\n@render logs --lines 10 --service backend\n```\n\n**Resultado esperado:**\n- ✅ Logs aparecen en Continue panel\n- ✅ Sin errores de autenticación\n- ✅ Timestamps y severidades visibles\n\n---\n\n## Integración con Render MCP\n\n### ¿Qué es Render MCP?\n\n**Render MCP** es un servidor MCP oficial que Render.com proporciona para acceder a:\n\n- 📊 **Logs** - Output de servicios en tiempo real\n- 🚀 **Deploys** - Historial y estado actual\n- 🔧 **Servicios** - Estado, métricas, health checks\n- 🌍 **Environments** - Variables y configuración\n- 📈 **Metrics** - CPU, memoria, latencia, errores\n- 🔐 **API Info** - Detalles de endpoints\n\n### Conectar con Render MCP\n\n#### Paso 1: Obtener API Key\n\n```\n1. Ir a https://dashboard.render.com\n2. Account → API Tokens\n3. Create New Token\n4. Copiar token (guardarlo seguro)\n```\n\n#### Paso 2: Guardar en Variables de Entorno\n\n```bash\n# .env local (DESARROLLO)\nRENDER_API_KEY=rnd_...\n\n# Para Render production (en Render dashboard):\n# No necesitas - MCP funciona dentro de su infraestructura\n```\n\n#### Paso 3: Configurar Endpoint\n\nRender MCP endpoint:\n```\nhttps://api.render.com/v1/render-mcp\n```\n\nHeaders requeridos:\n```\nAuthorization: Bearer ${RENDER_API_KEY}\nContent-Type: application/json\n```\n\n#### Paso 4: Validar Conexión\n\nEn Continue, ejecuta:\n\n```\n@render health\n```\n\nRespuesta esperada:\n```json\n{\n  \"status\": \"connected\",\n  \"region\": \"oregon\",\n  \"services\": 3,\n  \"uptime\": \"45 days\"\n}\n```\n\n### Comandos MCP Disponibles\n\n#### Logs\n```\n@render logs --service backend --lines 50\n@render logs --service backend --since 1h\n@render logs --service backend --error\n@render logs --follow  # real-time\n```\n\n#### Deploys\n```\n@render deploys --service backend --limit 10\n@render deploy-status <deploy-id>\n@render rollback <service-id> --to <previous-deploy>\n```\n\n#### Servicios\n```\n@render services\n@render service-status <service-id>\n@render service-metrics <service-id>\n```\n\n#### Environments\n```\n@render env-vars --service backend\n# NOTA: Solo metadata, nunca valores reales por seguridad\n```\n\n#### Métricas\n```\n@render metrics --service backend --period 1h\n@render health --all-services\n```\n\n---\n\n## Casos de Uso Reales\n\n### Caso 1: OAuth Google Callback Error\n\n**Escenario:** Usuario reporta \"Login with Google\" falla en producción\n\n**Flujo MCP:**\n\n```\n1. [Continue] @render logs --service backend --error --since 30m\n   ↓ Resultado:\n   [ERROR] /api/auth/google/callback: \"session support\" error\n   \n2. [Continue] Identificar línea exacta en backend/routes/auth.js\n   ↓ MCP correlaciona con endpoint\n   \n3. [Cline] Analizar stack trace\n   ↓ Propone: passport.authenticate needs session: false\n   \n4. [Cline] Sugerir fix en backend/routes/auth.js\n   ↓ Propone cambio específico\n   \n5. [Usuario] Revisa cambio propuesto\n   ↓ Si está bien, aplica\n```\n\n**Comando MCP:**\n```\n@render logs --service backend --error --search \"oauth\\|google\\|callback\"\n```\n\n---\n\n### Caso 2: MongoDB Connection Timeout\n\n**Escenario:** Requests de backend fallan con timeout\n\n**Flujo MCP:**\n\n```\n1. @render logs --service backend --error --lines 100\n   ↓ Logs muestran:\n   [ERROR] MongoNetworkError: connection timeout\n   \n2. @render service-metrics backend\n   ↓ Métricas muestran:\n   CPU: 5%, Memory: 40%, Connections: 145/150\n   \n3. @render env-vars --service backend\n   ↓ Verificar MONGO_URI esté correcto\n   \n4. Cline sugiere:\n   - Aumentar pool de conexiones\n   - Revisar MongoDB Atlas firewall rules\n   - Reducir timeout default\n```\n\n**Comandos:**\n```\n@render logs --service backend --search \"mongo\\|timeout\\|connection\"\n@render service-metrics backend --period 1h\n```\n\n---\n\n### Caso 3: Deploy Crash Loop\n\n**Escenario:** Backend crashea al deployar cambios\n\n**Flujo MCP:**\n\n```\n1. @render deploys --service backend --limit 5\n   ↓ Ver último deploy y estado\n   \n2. @render logs --service backend --since deploy-time\n   ↓ Ver logs exactos del crash\n   \n3. Cline analiza:\n   - Sintaxis error en código?\n   - Missing environment variable?\n   - Incompatible dependency?\n   \n4. Propone fix o rollback\n   @render rollback backend --to <previous-deploy>\n```\n\n**Comandos:**\n```\n@render deploys --service backend\n@render logs --service backend --since 5m\n@render service-status backend\n```\n\n---\n\n### Caso 4: Socket.io Disconnect Issues\n\n**Escenario:** Usuarios reportan desconexiones frecuentes\n\n**Flujo MCP:**\n\n```\n1. @render logs --service backend --search \"socket\\|disconnect\\|timeout\" --lines 200\n   ↓ Analizar patrones de disconnect\n   \n2. @render service-metrics backend --period 2h\n   ↓ Ver correlación con CPU/memoria/latencia\n   \n3. Cline analiza código Socket.io:\n   - Hay memory leaks?\n   - Heartbeat está configurado?\n   - Reconnection logic funciona?\n   \n4. Propone ajustes en backend/index.js\n```\n\n**Comandos:**\n```\n@render logs --follow --service backend --search \"socket\"\n@render service-metrics backend --include latency\n```\n\n---\n\n### Caso 5: Cold Start Issues\n\n**Escenario:** Primer request a backend tarda 20+ segundos\n\n**Flujo MCP:**\n\n```\n1. @render metrics --service backend --period 24h\n   ↓ Ver patrones de arranque\n   \n2. @render logs --service backend --since startup --lines 50\n   ↓ Ver qué tarda en startup\n   \n3. Cline sugiere:\n   - Lazy load dependencias?\n   - Pre-warm conexiones MongoDB?\n   - Render Cron job para keep-alive?\n   \n4. Implementar estrategia keep-alive\n```\n\n**Comandos:**\n```\n@render service-metrics backend --metric startup_time\n@render logs --service backend --search \"listening\\|started\"\n```\n\n---\n\n## Flujo de Trabajo\n\n### Flujo Diario (Desarrollador)\n\n#### 1. Morning Check\n```\nEn Continue, cada mañana:\n\n@render health --all-services\n@render logs --service backend --error --since 24h\n\n→ Identificar issues overnight\n```\n\n#### 2. During Development\n```\nMientras codificás:\n\n- Cambios en backend → npm run dev\n- Cambios en producción → @render logs --follow\n- Error aparece → @render logs --error --search \"<error-term>\"\n```\n\n#### 3. After Deploy\n```\nTras push a main (auto-deploy Render):\n\n@render deploys --service backend --limit 1\n@render logs --service backend --follow --since deploy-time\n\n→ Monitoring por 10 min\n```\n\n### Flujo de Debugging (Error en Producción)\n\n```\n┌─────────────────────────────────────────────┐\n│ 1. DETECCIÓN (Continue + MCP)               │\n│                                             │\n│ @render logs --error --since 5m             │\n│ → Identifica: 500 error en /api/projects    │\n└──────────────────┬──────────────────────────┘\n                   ↓\n┌─────────────────────────────────────────────┐\n│ 2. ANÁLISIS (Cline)                         │\n│                                             │\n│ Stack trace análisis:                       │\n│ - Línea del error                           │\n│ - Función involucrada                       │\n│ - Contexto (variables, estado)              │\n│                                             │\n│ Correlación con código:                     │\n│ - backend/routes/projects.js                │\n│ - backend/models/Project.js                 │\n│ - backend/services/project.service.js       │\n└──────────────────┬──────────────────────────┘\n                   ↓\n┌─────────────────────────────────────────────┐\n│ 3. HIPÓTESIS (Cline)                        │\n│                                             │\n│ Causas probables (ordenadas):               │\n│ 1. MongoDB connection timeout               │\n│ 2. Missing field en Project model           │\n│ 3. VERIFICACIÓN (Cline en código)           │\n│                                             │\n│ Revisar implementación:                     │\n│ - Middleware auth correcto?                 │\n│ - MongoDB query válida?                     │\n│ - Error handling presente?                  │\n└──────────────────┬──────────────────────────┘\n                   ↓\n┌─────────────────────────────────────────────┐\n│ 5. FIX PROPUESTO (Cline)                    │\n│                                             │\n│ Cambios recomendados:                       │\n│ - Archivo: backend/routes/projects.js:45    │\n│ - Cambio: try-catch + validación input      │\n│ - Impacto: Bajo (solo error handling)       │\n│                                             │\n│ Developer revisa + aplica                   │\n└──────────────────┬──────────────────────────┘\n                   ↓\n┌─────────────────────────────────────────────┐\n│ 6. VALIDACIÓN (Continue)                    │\n│                                             │\n│ Post-fix verification:                      │\n│ @render logs --service backend --error      │\n│                                             │\n│ → Sin errores por 10 min                    │\n│ → ✅ PROBLEMA RESUELTO                      │\n└─────────────────────────────────────────────┘\n```\n\n### Flujo para Agentes IA Autónomos\n\n```\n┌─────────────────────────────────────────────┐\n│ Cline (Autonomous Debug Agent)              │\n└──────────────────┬──────────────────────────┘\n                   │\n   ┌───────────────┼───────────────┐\n   ↓               ↓               ↓\n[Logs]        [Code Analysis]  [Cross-Reference]\n - Fetch       - Read files    - Stack trace\n - Parse       - Syntax check  - Call stack\n - Filter      - Logic review  - Dependencies\n   │               │               │\n   └───────────────┼───────────────┘\n                   ↓\n           [Hypothesis]\n         Generate 2-3 causes\n         Rank by probability\n                   ↓\n        [Suggest Fix]\n      backend/routes/...\n      Add validation\n      Error handling\n                   ↓\n       [User Approval]\n       Review suggested\n       Apply or reject\n```\n\n---\n\n## Seguridad\n\n### 🔐 Manejo de API Keys\n\n**NUNCA hacer:**\n```javascript\n❌ // PELIGRO: Hardcodeado\nconst apiKey = \"rnd_abc123...\";\n\n❌ // PELIGRO: En código\nconst headers = { Authorization: \"Bearer rnd_...\" };\n\n❌ // PELIGRO: En logs\nconsole.log(\"API Key: \" + process.env.RENDER_API_KEY);\n```\n\n**SIEMPRE hacer:**\n```bash\n# 1. Variables de entorno\nexport RENDER_API_KEY=\"rnd_...\"\n\n# 2. Archivo .env local (nunca commitear)\nRENDER_API_KEY=rnd_...\n\n# 3. Gitignore protege .env\necho \".env\" >> .gitignore\n\n# 4. En Render dashboard → Environment variables\n# NO en código\n```\n\n**Verificar .gitignore:**\n```bash\ncat .gitignore | grep \".env\"\n# Debe tener: .env, .env.local, .env.*.local\n```\n\n### 🚨 Riesgos Comunes\n\n| Riesgo | Síntomas | Mitigación |\n|--------|----------|------------|\n| **API Key expuesta** | GitHub detects secret | Regenerar en Render dashboard |\n| **Logs con info sensible** | Tokens/passwords en logs | Sanitizar logs, revisar console.log |\n| **CORS abierto** | Anyone can access MCP | Restringir a IPs conocidas |\n| **Env vars visibles** | @render env-vars muestra TODO | MCP solo muestra metadata, nunca valores |\n\n### ✅ Buenas Prácticas\n\n1. **Rotar API Keys regularmente**\n   ```bash\n   # Cada 3 meses\n   1. Generar nueva key en Render\n   2. Actualizar en .env local\n   3. Regenerar key vieja en Render\n   ```\n\n2. **Limitar permisos MCP**\n   - Solo acceso a servicios necesarios\n   - No dar acceso a environment variables de prod\n   - Usar scope mínimo en API tokens\n\n3. **Audit de logs**\n   - No loguear passwords/tokens\n   - Sanitizar entrada de usuario\n   - Revisar logs periódicamente\n\n4. **Separar Dev/Prod**\n   - Desarrollo: token con acceso limitado\n   - Producción: nunca usar MCP local (usar Render webhooks)\n   - Staging: token separado con permisos staging\n\n---\n\n## Limitaciones\n\n### Limitaciones de MCP\n\n1. **No modifica infraestructura**\n   - Leer logs: ✅\n   - Revisar estado: ✅\n   - Rollback deploy: ⚠️ (requiere confirmación)\n   - Escalar servicios: ❌ (manual en dashboard)\n\n2. **Latencia**\n   - Logs tienen ~2-5s de delay\n   - Métricas tienen ~30s de delay\n   - Real-time streaming: ✅ pero puede ser lento\n\n3. **Volumen de datos**\n   - Max 1000 líneas de logs por query\n   - Max 24h de datos históricos\n   - Datos más viejos requieren export manual\n\n4. **Seguridad**\n   - MCP no encripta tráfico (depende de HTTPS)\n   - API Key en tránsito debe ser HTTPS\n   - No soporta 2FA para MCP token\n\n### Limitaciones de Continue\n\n1. **Context window**\n   - Max ~100K tokens por conversación\n   - Logs muy largos pueden truncarse\n   - Solución: Filtrar logs con `--search`\n\n2. **File operations**\n   - No puede editar archivos sin confirmación\n   - Cambios deben ser revisados manualmente\n   - No soporta atomic transactions\n\n3. **Real-time sync**\n   - Cambios en GitHub no se reflejan instant\n   - Requiere `git pull` manual\n   - Cline lee archivos locales (el repo debe estar actualizado)\n\n### Limitaciones de Cline\n\n1. **Reasoning complexity**\n   - Fallos complejos pueden requerir human input\n   - No siempre identifica causa correcta\n   - Puede sugerir \"false positives\"\n\n2. **Autonomy**\n   - Cline NO aplicará cambios sin confirmación\n   - Requiere aprobación manual del developer\n   - Esto es por diseño (seguridad)\n\n3. **External APIs**\n   - Cline no puede llamar APIs directamente\n   - Depende de Continue para MCP\n   - Integración limitada con otros servicios\n\n---\n\n## Troubleshooting\n\n### Problema 1: \"MCP Connection Failed\"\n\n**Síntomas:**\n```\nError: Could not connect to Render MCP server\nError: Authorization failed (401)\n```\n\n**Soluciones:**\n\n1. Verificar API Key\n   ```bash\n   echo $RENDER_API_KEY\n   # Debe tener valor, NO vacio\n   \n   # Si vacío:\n   export RENDER_API_KEY=\"rnd_your_key_here\"\n   ```\n\n2. Verificar .env está cargado\n   ```bash\n   # Reload VS Code: Cmd+Shift+P → Reload Window\n   # O reiniciar Continue extension\n   ```\n\n3. Verificar API Key válida\n   ```bash\n   # En Render dashboard:\n   # Account → API Tokens → Verificar token no expiró\n   ```\n\n4. Verificar red\n   ```bash\n   curl -H \"Authorization: Bearer $RENDER_API_KEY\" \\\n     https://api.render.com/v1/render-mcp/health\n   # Debe retornar 200 OK\n   ```\n\n---\n\n### Problema 2: \"No Logs Returned\"\n\n**Síntomas:**\n```\n@render logs --service backend\n→ (empty result)\n```\n\n**Soluciones:**\n\n1. Verificar nombre del servicio\n   ```bash\n   @render services\n   # Ver lista exacta de servicios\n   # Usar nombre exacto: \"reqtracker-backend\", NO \"backend\"\n   ```\n\n2. Verificar tiempo\n   ```bash\n   # Logs hace más de 24h no están disponibles\n   @render logs --service backend --since 1h\n   ```\n\n3. Verificar filtro\n   ```bash\n   # Query muy restrictiva\n   @render logs --service backend --lines 50  # Sin filtro\n   @render logs --service backend --search \"error\" --lines 50\n   ```\n\n4. Verificar permisos\n   - API Key tiene acceso al servicio?\n   - Token no expiró?\n   - Servicio existe y está corriendo?\n\n---\n\n### Problema 3: \"Cline Cannot Find Files\"\n\n**Síntomas:**\n```\nCline: Cannot open backend/routes/auth.js\nError: File not found\n```\n\n**Soluciones:**\n\n1. Verificar repo está actualizado\n   ```bash\n   git status\n   git pull origin main\n   ```\n\n2. Verificar path en Cline\n   ```\n   ✅ backend/routes/auth.js\n   ❌ /backend/routes/auth.js  (absolute path wrong)\n   ❌ backend\\routes\\auth.js   (Windows backslash wrong)\n   ```\n\n3. Reiniciar Cline\n   ```\n   Cmd+Shift+P → Cline: Reset\n   ```\n\n4. Verificar folder está abierto\n   ```\n   File → Open Folder → /path/to/reqtracker\n   ```\n\n---\n\n### Problema 4: \"Token Expired\"\n\n**Síntomas:**\n```\nError: 401 Unauthorized\nError: Authorization token expired\n```\n\n**Soluciones:**\n\n1. Regenerar API Key\n   ```\n   Render dashboard → Account → API Tokens\n   → Delete old token\n   → Create New Token\n   ```\n\n2. Actualizar .env\n   ```bash\n   # Update .env with new key\n   RENDER_API_KEY=\"rnd_new_key_here\"\n   \n   # Reload VS Code\n   Cmd+Shift+P → Reload Window\n   ```\n\n3. Verificar expiración\n   ```\n   Render → API Tokens → Ver fecha de expiración\n   Tokens expiran después de 2 años\n   ```\n\n---\n\n### Problema 5: \"CORS Error\"\n\n**Síntomas:**\n```\nError: CORS policy blocked request\nError: No 'Access-Control-Allow-Origin' header\n```\n\n**Soluciones:**\n\n1. Verificar CORS en backend/index.js\n   ```javascript\n   // Debe tener CORS configurado\n   const cors = require('cors');\n   app.use(cors({\n     origin: [\"http://localhost:5173\", \"https://...\"],\n     credentials: true\n   }));\n   ```\n\n2. Verificar origin correcto\n   ```bash\n   # Frontend local\n   http://localhost:5173\n   \n   # Frontend prod (Render)\n   https://reqtracker-frontend.onrender.com\n   ```\n\n3. Reiniciar backend\n   ```bash\n   # Si cambiaste CORS config\n   cd backend\n   npm run dev\n   ```\n\n---\n\n## Ejemplos de Prompts Útiles\n\n### Continue Prompts\n\n```\n# Ver logs
